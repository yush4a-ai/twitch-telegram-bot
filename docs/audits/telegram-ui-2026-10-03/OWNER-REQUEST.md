Источники:3b3387d3-d361-498d-9e66-dc22af73b41f и дополнение a3e151de-063e-49df-82d4-6049ee56d689.

Новая задача по TwitchSignalBot.

Рабочая папка:
C:\Users\yusha\Desktop\cloude\TG-BOT.(TwtichSignal)

Ветка:
autonomous/twitchsignal-roadmap

Цель:
полностью привести ОБЫЧНЫЙ Telegram-интерфейс бота
(сообщения + inline-кнопки)
к простому и понятному виду.

Mini App уже является основным полноценным интерфейсом.

Главная задача обычного Telegram UI:
НЕ пугать нового пользователя количеством функций.

Новый человек должен сразу понимать:
1. можно пользоваться полноценным Mini App;
2. можно пользоваться обычными кнопками Telegram;
3. основные действия доступны сразу;
4. редкие функции никуда не исчезли, но спрятаны глубже.

Production не трогать.
Работать сначала локально, затем только staging @TwitchSignalTestbot
после тестов.

15. PAYMENT FLOW В ОБЫЧНОМ TELEGRAM
==================================================

Требование менеджера Platega
должно выполняться и здесь.

Путь должен быть полноценным:

Тариф
→ точная цена
→ кнопка «Оформить»
→ выбор способа оплаты
→ результат.

Способы:

[ Telegram Stars ]
[ СБП ]
[ Банковская карта ]

На ПЕРВОМ staging release
реальные платежи всё ещё OFF.

После выбора любого способа
показывать честную заглушку:

«Оплата временно недоступна.
Мы заканчиваем подключение платёжной системы.»

«Платёж не создан.
Деньги не списаны.»

НЕ:

- отправлять Platega POST;
- создавать Stars invoice;
- делать fake success;
- выдавать Plus;
- менять ledger как paid;
- включать auto-renew.

Кнопки при этом должны быть кликабельны.

Это важно для merchant moderation.

29. ПОСТОЯННЫЙ БЫСТРЫЙ ВХОД В МЕНЮ БЕЗ /start
==================================================

Дополнительное UX-требование владельца.

Пользователь не должен быть вынужден писать:

/start

чтобы снова попасть в главное обычное меню бота.

Нужно обеспечить два постоянных способа входа:

1. системная Telegram MenuButton:
   «Приложение»
   → открывает текущий Mini App /app;

2. быстрый доступ к обычному Telegram-меню
   через persistent ReplyKeyboardMarkup.

ВАЖНО:

Telegram даёт только один системный Bot Menu Button.
Он уже используется для «Приложение».

Не заменять его на MenuButtonCommands.

Не пытаться программно менять
emoji / microphone / client controls справа —
бот ими не управляет.

Использовать официальный ReplyKeyboardMarkup
как второй UX-слой.

30. PERSISTENT REPLY KEYBOARD
==================================================

Не использовать ReplyKeyboardRemove
после обычных пользовательских сценариев,
если для этого нет специальной причины.

При нажатии:

Меню

бот НЕ должен воспринимать это
как обычный пользовательский текст.

Это системный UX action:

→ открыть/прислать актуальное главное меню.

32. /start ОСТАЁТСЯ, НО НЕ ТРЕБУЕТСЯ
==================================================

Не удалять /start.

Он нужен для:

- первого запуска;
- deep links;
- backward compatibility;
- Telegram Start flow;
- восстановления состояния.

Но пользовательскому UX

После первого взаимодействия
человек всегда должен иметь понятный путь:
