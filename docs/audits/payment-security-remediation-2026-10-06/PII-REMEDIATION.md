## Что сделано

1. **Новая чистая линия.** Ветка `remediation/payment-security-2026-10-06` создана от
   `origin/main` (`9fceaf9`) — безопасной базы без этих коммитов. Вся дальнейшая работа
   (исправления аудита) идёт только в ней.
2. **Проверка новой линии.** `git merge-base --is-ancestor 022779b HEAD` и то же для
   `216c97c` → оба недостижимы из новой ветки.
3. **Защита от случайной публикации.** `scripts/git-hooks/pre-push` (установлен локально в
   `.git/hooks/pre-push`) отклоняет push, если:
   - отправляется ветка `autonomous/twitchsignal-roadmap`, ветка `backup/pre-pd-cleanup` или
     тег `pre-pd-cleanup-20261005`;
   - любой отправляемый коммит имеет в предках `022779b` или `216c97c` (то есть защита
     работает и при переименовании ветки).
   Проверено тремя прогонами: чистая ветка — пропуск, небезопасная ссылка — отказ, ветка с
   другим именем и PII в истории — отказ. Осознанный обход: `ALLOW_PII_PUSH=1`.
4. **Явная пометка.** Созданы дубликаты-предупреждения `DO-NOT-PUSH/autonomous-twitchsignal-roadmap`
   и `DO-NOT-PUSH/pre-pd-cleanup-20261005`; исходные ссылки не удалялись. Локальная заметка
   `.git/DO-NOT-PUSH.md` (в коммиты не попадает) перечисляет опасные ссылки.

## Что осталось владельцу (необратимо, требует отдельного разрешения)

Порядок окончательной очистки локального репозитория. Выполнять **только** после того, как
рабочая линия `remediation/*` проверена и (при необходимости) опубликована.

1. Сделать резервную копию локальных данных вне Git (архив каталога или bundle тех веток,
   которые нужны как история) — потому что шаг 3 необратим.
2. Убедиться, что ничего не потеряно: `git log --oneline remediation/payment-security-2026-10-06 | head`,
   `git status` чистый, все нужные изменения есть в новых коммитах.
3. Переписать историю опасных ссылок (пример, выполнять осознанно):
   - `git filter-repo --path docs/STATUS.md --path docs/legal/manifest.json --invert-paths --refs autonomous/twitchsignal-roadmap`
     (или `--replace-text` с файлом замены значений);
   - либо просто удалить локальные ссылки: `git branch -D DO-NOT-PUSH/autonomous-twitchsignal-roadmap`,
     `git branch -D autonomous/twitchsignal-roadmap` (после архивации), `git tag -d DO-NOT-PUSH/pre-pd-cleanup-20261005 pre-pd-cleanup-20261005`,
     `git branch -D backup/pre-pd-cleanup`.
4. Только после этого: `git reflog expire --expire=now --all && git gc --prune=now --aggressive`.
5. Проверить результат: `git rev-list --all | Measure-Object` до и после, поиск по всей
   доступной истории на предмет личных данных (без вывода значений), `git fsck --no-reflogs`.
6. Не пушить переписанную историю туда, где она уже могла быть: на GitHub этих коммитов нет,
   поэтому force-push не требуется и не должен выполняться.

## Правило на будущее

Личные и юридические данные владельца не попадают в репозиторий: в документах остаются
ссылки на переменные окружения (`LEGAL_OPERATOR`, `LEGAL_OPERATOR_ADDRESS`, `SUPPORT_USERNAME`,
`SUPPORT_EMAIL`). Перед коммитом документов полезно проверять наличие длинных цифровых
последовательностей и личных почтовых доменов.
