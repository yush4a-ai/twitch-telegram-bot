# Политика конфиденциальности TwitchSignalBot

Редакция для проверки: 2 октября 2026 года.

**Черновик. Не опубликован как действующая политика.** Владелец должен заполнить сведения об операторе, контакт, применимые основания обработки и условия хранения. Platega пока не подключена; платёжный раздел ниже описывает предполагаемую интеграцию и должен быть обновлён перед её включением.

## 1. Сервис и оператор

TwitchSignalBot помогает получать уведомления об эфирах Twitch, управлять отслеживаемыми стримерами и публиковать сообщения в подключённых Telegram-сообществах. В Mini App пользователь управляет теми же подписками и настройками, что в боте.

Оператор: **[реальные сведения владельца — заполнить]**. Контакт по вопросам сервиса и данных: **[реальный Telegram username и/или support email — заполнить]**. Для тестового этапа используется @TwitchSignalTestbot; это имя бота не заменяет контакт поддержки.

## 2. Данные и цели обработки

| Категория | Для чего используется |
|---|---|
| Telegram user ID; username/display name, если они переданы Telegram | Проверить вход и принадлежность настроек, адресовать уведомления; показать имя. Username не подтверждает право владения |
| Twitch login/broadcaster ID, подтверждённая связь с Telegram | Найти стримера, наблюдать эфир, проверить право стримера управлять публикациями |
| OAuth credentials при явном подключении Twitch | Выполнить разрешённые запросы Twitch и поддерживать подключение; не публиковать token в интерфейсе |
| Список отслеживаемых стримеров, настройки уведомлений/тихих часов/Plus, папки, напоминания | Применять выбранные пользователем правила, лимиты и время доставки |
| Telegram channel/chat identifiers и проверенный статус подключения | Проверить разрешённое размещение и отправлять/обновлять собственные сообщения бота; старые группы сохраняются |
| Шаблоны, кнопки, варианты постов, IDs отправленных сообщений | Подготовить публикацию и обновлять текущий пост; учитывать подтверждённые отправки |
| Метаданные эфиров и доставки, история событий/итоги | Показывать фактические события и отчёты. Если включены существующие отчёты чата Twitch, обрабатываются ники участников, агрегаты активности/рейдов; это отдельная действующая функция, а не новая click-аналитика |
| Время проверенного входа, технические ID/ошибки запросов и ограничители частоты | Защита входа, устранение ошибок, предотвращение повторов и злоупотреблений |
| Содержание обращения в поддержку, добровольно отправленные пользователем сведения | Разобрать вопрос о доступе, доставке, данных или платеже после появления реального контакта |

Наше приложение не требует паспорт, изображение документа или банковскую карту для Free-функций. Onboarding/KYC владельца у платёжного провайдера проходит отдельно, непосредственно у провайдера. Не отправляйте секреты или данные карты в поддержку.

## 3. Платежи: планируемое изменение

Сейчас денежная касса не подключена; существующий billing использует mock TEST и журнал тестовых заказов. После согласования интеграции сервер будет хранить внутренний order ID, проверенный Telegram buyer, product/period/amount/currency, provider transaction ID, финансовый статус, даты и источник доступа. Эти данные нужны для сверки оплаты, единственной выдачи Plus, поддержки и возврата.

После подключения Platega необходимые сумма/валюта, server order reference и согласованные metadata будут передаваться Platega. Сейчас передачи в Platega из приложения нет. При подключении Stars соответствующие invoice/payment данные обрабатывает Telegram. Данные банковской карты вводятся на стороне провайдера и через наш сервер не проходят. Налоговый чек и запись заказа — разные документы; порядок НПД ещё должен подтвердить владелец.

## 4. Сервисы и получатели

Telegram обрабатывает Telegram-вход, сообщения, данные каналов и доступные события SDK. Twitch получает необходимые API/OAuth-запросы для наблюдения/подключения. Серверное размещение проекта — Railway; на hosting находится рабочая база и сервисные процессы. Данные, отправленные в подключённый канал/старую группу, видят участники согласно настройкам самого сообщества.

Platega — предполагаемый будущий получатель платёжных данных только после подключения. Stripe/Paddle и другие кассы не подключены; передача им не заявляется. В отдельном локальном дизайн-макете нет платёжного API и доступа к рабочей базе.

Состав данных инфраструктурных logs, место размещения, доступ операторов hosting и условия трансграничной обработки владелец должен подтвердить для действующего окружения. Документ не обещает хранение только в одной стране без проверки размещения.

## 5. Хранение и защита

Подписки и настройки хранятся для работы сервиса. Истечение Plus отключает платный эффект, сохраняя настройки; оно не является удалением аккаунта. Личная Viewer-история в текущем коде имеет техническое хранение 30 суток. У иных отчётов, технических logs, OAuth, заказов и резервных копий свои сроки; их полную таблицу и основания владелец должен утвердить перед публикацией политики. Не обещаем удаление всех данных за неподтверждённый срок.

Код сервиса предусматривает проверку Telegram-подписи, серверные права, ограничение запросов и защиту OAuth credentials; deployment/settings нужно проверить отдельно. Секреты платёжного провайдера не предназначены для клиента, Git или screenshots. Полные credentials и данные карт в платёжный audit не включаются. Наличие этих требований не означает завершённый аудит действующей инфраструктуры.

## 6. Обращения по данным

Пользователь может обратиться через **[контакт владельца]** по вопросам данных, исправления сведений, прекращения обработки или удаления связанных данных. Для защиты аккаунта оператор проверяет принадлежность обращения; не требует отправлять платёжные секреты. Объём удаления и данные, которые нужно сохранять по применимым обязательствам, оператор объясняет в ответе.

Удаление отслеживаемого стримера в приложении удаляет связанную подписку и её правила. Оно не удаляет финансовый журнал или все резервные копии. Подтверждённый полный запрос на удаление аккаунта — отдельная процедура; автоматический self-service сейчас не обещается.

## 7. Редакции

Действующая редакция должна быть доступна в разделе «Документы» и до покупки. Существенные изменения целей/состава обработки должны пройти проверку владельца и быть раскрыты пользователю до применения. Новая дата сама по себе не заменяет необходимое правовое основание или согласие.
