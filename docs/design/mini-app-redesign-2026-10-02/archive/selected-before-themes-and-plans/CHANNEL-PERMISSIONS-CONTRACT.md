## Единое требование

Для новых каналов: сервер подтверждает `chat.type == channel`, право текущего пользователя управлять выбранным каналом, роль бота administrator/creator и право публикации `can_post_messages == True` для administrator. Результаты Telegram, идентичность бота и принадлежность выбранного канала перепроверяются; режим приложения и клиентский флаг не являются разрешением.

Инструкция пользователю: назначить **@TwitchSignalTestbot** администратором и включить **«Публикация сообщений»**. `can_edit_messages` описано как редактирование чужих сообщений и закрепление; текущий сценарий их не использует. Удаление собственных исходящих сообщений канала допускается при `can_post_messages`, с ограничением `deleteMessage` по возрасту. Дополнительные права на чужие посты, подписчиков и назначение администраторов не запрашиваются. [ChatMemberAdministrator](https://core.telegram.org/bots/api#chatmemberadministrator), [deleteMessage](https://core.telegram.org/bots/api#deletemessage).

Обновление собственных постов сопоставлено с методами [editMessageText](https://core.telegram.org/bots/api#editmessagetext), [editMessageCaption](https://core.telegram.org/bots/api#editmessagecaption), [editMessageMedia](https://core.telegram.org/bots/api#editmessagemedia). Вывод о ненужности права на чужие сообщения основан на этом сопоставлении кода и документации. Это **не фактический Telegram-тест** минимального набора прав.

Перед переносом серверная проверка и инструкция должны соответствовать этому контракту в одном проверенном изменении. Нельзя разместить новую инструкцию поверх старого скрытого требования `can_edit_messages`. Текущий helper сохраняется до утверждения плана; старые группы не удаляются и не переводятся на новую политику каналов.

## Результаты и проверки переноса

- Отдельные результаты: бот отсутствует, участник, нет публикации, проверяется, подтверждено, Telegram недоступен, отмена, устаревший запрос. Сетевая ошибка означает неизвестный результат, а не отсутствие права.
- Клиент показывает успех только по серверному результату; выбор канала не включает публикации и не отправляет тестовый пост.
- Сервер принимает ID поста для обновления только из доверенного состояния собственного отправленного сообщения. Произвольный ID из клиентского запроса не подходит.
- Нужны отрицательные проверки чужого канала/поста, обычного участника, group в новом пути, пропавших прав, неполного ответа, недоступного Telegram, replay/просроченного запроса. Free-подключение сохраняется; оформление Plus требует отдельного действующего доступа.
- На разрешённом тестовом канале отдельно проверить отправку, обновление текста/подписи/медиа и удаление собственного свежего поста с публикацией и **без** `can_edit_messages`. Старый пост вне срока удаления не должен приводить к просьбе выдать все права. Реальные проверки пока **NOT TESTED**; отправки без отдельного разрешения запрещены.

## Ссылка выбранного канала

«Открыть канал» доступно только по проверенным серверным метаданным того же канала. Не создавать ссылку на настройки администраторов или неизвестный invite. В предпросмотре основной условный канал не имеет ссылки; `channelLink=public` — явно условный сценарий с реальным публичным URL [Telegram](https://t.me/telegram). `channelLink=invalid` проверяет отказ от `javascript:`. Эти параметры — только данные локального макета, не доказательство серверной проверки или управления каналом.
