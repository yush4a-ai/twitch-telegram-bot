## Согласуемый путь

«Возможности Plus» → Viewer/Streamer → состав + точная цена/месяц → «Подключить … — … ₽» → «Как оплатить?» на разрешённой площадке → «Оплатить» → **«Оплата временно недоступна. Мы заканчиваем подключение платёжной системы.»**

Кнопки работают даже до подключения API, без фиктивного success, заказа у провайдера, списания и выдачи Plus. Не маскировать незавершённое подключение disabled-кнопкой без объяснения. UI недоступного upgrade открывает объяснение; финансовая формула не появляется.

Покупка начинается внутри бота / Mini App: Stars через Telegram; СБП/карта через открыто названную Platega. Владелец принял платформенный риск; скрытие методов и обходы запрещены. XTR TBD. Реализация P01–P21 разрешена; bank approval остаётся NOT READY до документов/реального контакта и приёмки.

## Данные владельца, которые нельзя придумать

1. SUPPORT_USERNAME и/или SUPPORT_EMAIL: отдельный реальный username без группы; email только предоставленный владельцем. Ни одного контакта ещё нет. Возможность двух контактов сохраняем.
2. Реальные сведения исполнителя/оператора и обязательные реквизиты для применимой схемы, страна/юрисдикция. Самозанятый не заменяется выдуманным ИП/ООО.
3. Определение месяца, anchor доступа, продление заранее/активный план и Viewer→Streamer formula.
4. Возвраты/chargeback→доступ, поддержка/разбор и правила чеков НПД по подтверждённому договору.
5. XTR-цены; merchant/test подтверждения Platega. Точка покупки внутри Mini App уже утверждена.
6. Фактические сроки хранения/backup/logs, размещение и порядок запросов по данным.
7. Несекретные ответы merchant manager о методах/metadata/test/schema/idempotency/восстановлении.

Credentials PLATEGA_MERCHANT_ID/PLATEGA_SECRET владелец вводит самостоятельно в Railway staging после согласования внедрения. Их значения не нужны в чате или для этой заглушки. Callback URL в spec пока зарезервирован, не активен.
