# Подключение реальной кассы Platega: состояние и что осталось владельцу

Дата: 08.10.2026. Ветка: `remediation/payment-security-2026-10-06`. Коммит кода: `a8575c0`.
Статус: код подключения готов и проверен локально. Реальные списания, переменные и
контракт production **не менялись**: включение банковского канала — отдельное решение владельца.

## 1. Что уже сделано в коде

- `bot/platega_transport.py` — настоящий HTTPS-транспорт к `https://app.platega.io`
  (единственный разрешённый хост, редиректы запрещены, ответ ограничен 64 КБ,
  заголовки с секретом нигде не журналируются).
- `bot/platega_provider.py` — адаптер принимает объявленный транспорт
  (`trusted_contract`), объявляет `money_capable`, требует подтверждённое имя
  покупателя и умеет закрывать транспорт.
- `bot/payment_web.py` — публичный `POST /payments/platega/callback`; монтируется
  только когда владелец разрешил банковский канал и провайдер допущен. Подлинность
  подтверждают заголовки `X-MerchantId`/`X-Secret`, локальный loopback-контракт сохранён.
- `bot/billing.py` — готовность сервиса считается по `money_capable`; без
  подтверждённого имени покупателя счёт не создаётся; есть `public_callback_ready()`.
- `bot/platega_runtime.py`, `bot/config.py`, `main.py` — провайдер собирается только
  при ключах **и** явном флаге; банковский канал получил отдельный сервис (звёзды и
  СБП/карта больше не мешают друг другу); воркер сверки теперь вызывает
  `reconcile_due`, то есть подтверждает оплату каноническим запросом статуса.
- Мини-апп: СБП и карта идут в банковский сервис, имя покупателя берётся из
  подписанных данных Telegram (не выдумывается).
- Тексты бота о способах оплаты говорят по фактической готовности канала.

## 2. Что взять в личном кабинете Platega

Страница «Настройки» (проверено владельцем 08.10.2026):

| Поле ЛК | Куда идёт |
|---|---|
| ID мерчанта (UUID) | переменная `PLATEGA_MERCHANT_ID` |
| API ключ (он же `X-Secret`) | переменная `PLATEGA_SECRET` |
| Callback URL | `https://worker-production-cee5.up.railway.app/payments/platega/callback` |

Важно: полный API-ключ виден **только один раз** сразу после генерации. Ключи
вводит владелец в Railway → Variables; в чат, отчёты и репозиторий они не попадают.

Callback принимает только HTTPS, публичный домен и валидный сертификат; ответ
ожидается до 60 секунд, затем до 3 повторов с интервалом 5 минут.

## 3. Переменные production для банковского канала

Порядок и состав (значения вводит владелец, не исполнитель):

1. `PLATEGA_MERCHANT_ID`, `PLATEGA_SECRET` — из ЛК.
2. `BILLING_ALLOW_EXTERNAL=1` — явное разрешение банковского канала.
3. Уже действующие денежные флаги: `BILLING_MODE=sandbox`, `BILLING_TARGET_VERIFIED=1`,
   `BILLING_PERIOD_APPROVED=1`, `BILLING_REFUND_APPROVED=1`.
4. Необязательные уточнения (по умолчанию безопасные):
   - `PLATEGA_HOSTED_HOSTS` — домены, на которые Platega отдаёт ссылку оплаты
     (по умолчанию `pay.platega.io`);
   - `PLATEGA_STATUS_METHODS` — соответствие метода в ответе о статусе и нашего
     способа (по умолчанию `SBPQR:sbp`).

## 4. Что блокирует включение в production

1. **Контракт допуска.** `PRODUCTION_PAYMENT_POLICY=off` обязателен для действующего
   контракта и одновременно глушит банковский канал (`bot/production_admission.py`,
   `bot/payment_policy.py`). Пока контракт не изменён отдельным решением владельца,
   СБП и карта в production останутся выключенными, даже если ключи и флаги заданы.
2. **Открытые денежные решения владельца** (`OWNER-INPUTS-FOR-LAUNCH.md`): точное
   определение «1 месяц», правила возврата и chargeback, апгрейд Viewer → Streamer,
   цены в XTR, реальные контакты поддержки, данные оператора, схема чеков НПД,
   сроки хранения.
3. **Документы.** Публичные `/app/legal/*` пока отдают 503: без опубликованных
   Privacy и Agreement оплату включать нельзя.
4. **Риск платформы Telegram.** Цифровой доступ внутри бота и мини-аппа Telegram
   ожидает продавать через Stars; продажа того же доступа по СБП и карте внутри
   мини-аппа — решение владельца с известным риском для бота (отмечено в
   `docs/audits/2026-10-02-platega-api-research.md`, раздел «Площадка продажи»).

## 5. Что уточнить у менеджера Platega

- Есть ли тестовый режим и тестовые карты; платный ли он.
- Разрешены ли методы `2` (СБП QR) и `11` (карта) и суммы 150/300 ₽ на этом мерчанте.
- Обязательна ли `metadata` (`userId`, `userName`) и допустимый формат имени.
- Семантика `CHARGEBACKED` и написание поля `mechantId` в ответе о статусе.
- Идемпотентность `POST /transaction/process` и как найти транзакцию, если ответ
  не пришёл: у нас повтор POST запрещён, неизвестный исход уходит на ручную сверку.
- Как выглядит строковое имя карточного метода в ответе о статусе (сейчас
  подтверждён только `SBPQR`; без этого карта не сможет подтвердиться автоматически).
