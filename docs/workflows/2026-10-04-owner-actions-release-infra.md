## 1. Разрешение токену на файлы workflow

**Почему:** GitHub отклоняет push файлов `.github/workflows/*` с сообщением
«refusing to allow a Personal Access Token to create or update workflow without
`workflow` scope». Пока этого нет, CI-файлы лежат только локально и проверки в
облаке не запускаются.

**Классический токен:** GitHub → Settings → Developer settings → Personal access
tokens → выбрать токен → включить галочку **`workflow`** → Save.

**Fine-grained токен:** тот же раздел → у токена в разделе Permissions найти
**Workflows** → выставить **Read and write** → Save.

**Альтернатива без токена:** добавить два файла через веб-интерфейс GitHub
(Add file → Create new file) по путям `.github/workflows/tests.yml` и
`.github/workflows/staging-deploy.yml`, скопировав содержимое из репозитория
на диске.

**Как проверить:** после этого `git push origin autonomous/twitchsignal-roadmap`
должен пройти, а во вкладке Actions появится запуск `tests`.

## 2. Защита ветки `main`

**Почему:** ветка `main` синхронизирована с фактическим кодом, но её всё ещё
можно перезаписать или удалить случайным действием.

**Где:** GitHub → репозиторий → Settings → Branches → **Add branch protection
rule** (или Add rule) → Branch name pattern: `main`.

**Что включить минимально:**

- **Do not allow force pushes** (запрет перезаписи истории);
- **Do not allow deletions** (запрет удаления ветки).

Опционально, если захочется порядка: «Require a pull request before merging» —
тогда изменения попадают в `main` только через PR.
